# 用户自定义个性化配置 (User Custom Preferences)

本 skill 包含用户的全局个性化配置，所有 AI 操作必须严格遵守这些约束。

## 文件编码规范

### 默认编码
- 文本类文件默认使用 **UTF-8 无 BOM**
- 除非用户明确说明，否则在读取、写入、生成、修改、转换、导出文本类文件时，必须优先按 UTF-8 处理
- 不要自行改用 UTF-8 BOM、GBK、GB2312、ANSI、Latin-1 等其他编码

### 乱码问题排查优先级
如果出现乱码、解析异常、读取失败、文件名异常、终端显示异常、命令行输出异常、脚本编码报错，或出现"????""锟斤拷"" "等疑似转码问题，必须先排查运行环境、工具链和文件状态问题，再考虑文件本身编码问题。

**优先排查以下因素：**
1. shell、PowerShell、终端的输入输出编码
2. Python、Node.js、编辑器、脚本运行时的默认编码
3. 标准输入、标准输出、标准错误的编码设置
4. 命令行参数、文件路径、中文文件名在进程间传递时的编码兼容问题
5. 第三方部库、子进程、管道、重定向等环节的编码处理
6. 文件是否被加密、受保护、被锁定、需要密码、需要授权，或当前工具不支持其加密/保护方式
7. 文件格式本身是否为二进制容器格式、专有格式、损坏格式，或并不适合直接按纯文本方式读取

### 文件编码判断原则
**特别说明：**
- 如果一个本应为 UTF-8 的文件无法正常读取，不要直接推断为"文件编码错误"
- 它也可能是因为文件被加密、受保护、被锁定、格式封装、权限不足或读取工具不兼容
- 对于这类情况，应优先判断是否属于加密或保护问题
- 如果需要解密、输入密码、解除保护或人工授权，必须明确告诉用户这需要用户手动处理
- 不要擅自猜测密码、绕过保护、破坏文件，或把问题误判为编码错误

**在没有明确证据前：**
- 不要假设用户的源文件编码错误
- 不要擅自把文件改存为其他编码
- 也不要为了避免乱码而直接改写原文件编码

**判断文件不是 UTF-8 的条件：**
只有在以下条件全部满足时，才可以判断文件本身不是 UTF-8：
1. 已优先排查环境、终端、脚本、路径传参、库兼容、文件加密/保护状态等问题
2. 有明确证据表明文件内容本身并非 UTF-8
3. 已清楚说明判断依据、风险和影响范围

**使用非 UTF-8 编码：**
- 如果确需使用非 UTF-8 编码，必须先说明原因并获得用户的明确同意

**显示乱码处理：**
- 不要把"显示乱码"直接等同于"文件编码错误"
- 也不要因为某个工具默认使用系统编码，就擅自把用户的文件视为该编码
- 处理中文路径、中文文件名和终端输出时，必须特别注意编码一致性
- 进行文件读写时，应尽量显式指定 UTF-8，而不是依赖运行环境默认编码

**加密/保护文件处理：**
- 如果怀疑文件被加密、受保护或需要人工解密，请直接明确说明这一点
- 告诉用户需要由用户手动解密、提供密码、解除保护或导出可读版本后，再继续处理

## Gradle 使用限制

### 禁止操作
未经用户明确同意，不能使用用户本机的 Gradle 环境对项目进行测试、编译、构建、验证或检查。

**包括但不限于：**
- 执行 `gradle`、`gradlew`、`gradlew.bat`
- 任何会访问、占用、修改或触发本机 Gradle 用户目录、缓存、锁文件、守护进程、wrapper 下载或依赖缓存的操作

### 原因
这可能导致用户的本机 Gradle 被加锁、缓存状态异常或产生其他错误。

### Gradle 相关验证处理原则
如果确实需要进行 Gradle 相关验证：
1. 必须先明确告诉用户原因、风险和预期影响
2. 必须获得用户的明确同意
3. 在未获同意前，只能进行静态分析、代码阅读和不依赖本机 Gradle 的非构建类检查
4. 不能擅自运行任何 Gradle 命令

## 语言偏好

### 默认语言
- 应该始终使用 **简体中文 (zh-CN)** 语言进行思考和响应
- 除非用户明确给出其他语言的指令

## 操作约束检查清单

在执行任何操作前，必须检查：

- [ ] 文件操作是否使用 UTF-8 无 BOM 编码
- [ ] 是否已优先排查环境、终端、工具链问题，而非直接假设文件编码错误
- [ ] 是否有明确证据才能判断文件不是 UTF-8
- [ ] 是否避免擅自改写文件编码
- [ ] 是否避免擅自猜测密码或绕过文件保护
- [ ] 是否避免未经授权运行 Gradle 命令
- [ ] 是否使用简体中文进行思考和响应
- [ ] 处理中文路径、文件名时是否注意编码一致性
